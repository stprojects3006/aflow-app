TC-01: Test Protected Route Redirect ↑

RouteGET /owners/new
How to processSend HTTP request to protected route and verify 302 redirect to QueueIt
Expected Response302 Found with Location header pointing to QueueIt
HeadersUser-Agent, Accept (standard browser headers)
VerificationCheck response status is 302 and Location header contains queue-it.net
PrerequisitesQueueIt integration must be active and configured
Metrics to monitor: http_server_requests_seconds_count{uri="/owners/new",status="302"}, rate(http_server_requests_seconds_count{uri="/owners/new"}[5m])
Dashboard guidance: QueueIt Integration Dashboard → QueueIt Redirect Patterns
Steps: Run test, observe 302 redirect rate, verify Location header contains QueueIt URL.
Expected Result: 302 redirect to https://futuraforge.queue-it.net/

IP Diversity Testing

Implementation: Multiple ECS tasks with unique AWS public IPs for natural IP diversity.

IP Assignment Process

  1. Task Launch: Each ECS task launched independently
  2. Network Interface: Each task gets dedicated ENI (Elastic Network Interface)
  3. Private IP: Assigned from VPC subnet (10.0.1.0/24)
  4. Public IP: Auto-assigned from AWS public IP pool (3.x.x.x)
  5. IP Diversity: 10 tasks = 10 unique public IPs

Testing Commands

# Simple IP diversity test
./run-10-vu-tasks.sh

# Enhanced QueueIt test
./run-enhanced-queueit-test.sh

# Manual task launch
aws ecs run-task \
    --cluster k6-load-test-cluster \
    --task-definition k6-single-vu-task \
    --launch-type FARGATE \
    --network-configuration "awsvpcConfiguration={subnets=[subnet-097cbe067e542243a],securityGroups=[sg-0737d6eb4011e161c],assignPublicIp=ENABLED}" \
    --region us-east-1

Verification

  • CloudWatch Logs: Check for unique IP addresses per task
  • Grafana Dashboard: Monitor IP address distribution
  • Response Analysis: Verify requests from different IPs

Alerting

Critical Alerts:
  • QueueIt health endpoint down
  • High error rates (>10%)
  • No IP diversity detected
  • Protected routes not redirecting

Implementation Notes

Current Architecture:
  • Spring PetClinic with QueueIt integration
  • AWS ECS Fargate for IP diversity
  • Grafana + Prometheus for monitoring
  • K6 for load testing

Protected Routes

  • /owners/new: Protected route that redirects to QueueIt
  • /owners/edit/{id}: Protected route for editing owners
  • /pets/new: Protected route for adding pets
  • /visits/new: Protected route for adding visits

Public Routes

  • /: Public homepage
  • /owners/find: Public owner search
  • /vets: Public vet listing
  • /integration/queueit/health: Public health endpoint

Troubleshooting

Common Issues:
  • No 302 Redirects: Check QueueIt filter configuration
  • Health Endpoint Errors: Verify integration controller
  • No IP Diversity: Check ECS task configuration
  • High Error Rates: Review application logs

Best Practices

  • Test QueueIt integration separately from load testing
  • Monitor continuously using Grafana dashboards
  • Document test results and configurations
  • Clean up ECS tasks after testing to avoid costs
  • Set up alerts for critical metrics
