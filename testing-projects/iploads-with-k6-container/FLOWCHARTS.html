🔄 Complete Request Flow

End-to-End Request Flow Diagram

Complete Request Flow Steps:

  1. Deployment Phase
    • User Runs Deploy Script → Terraform Creates Infrastructure
    • VPC Created with Public Subnet → ECS Cluster Created
    • S3 Bucket Created → CloudWatch Logs Created
  2. Container Deployment
    • Docker Build → Push to ECR
    • ECS Task Definition → Fargate Task Execution
  3. IP Assignment
    • Fargate Allocates Resources → VPC Assigns Private IP
    • Public Subnet Assigns Public IP → Internet Gateway Routes Traffic
    • Security Group Validates → Task Ready
  4. Test Execution
    • K6 Container Starts → Load Test Script Loads
    • VUs Initialize → Generate HTTP Requests
  5. Network Flow
    • Container Network Interface → Public IP: 3.x.x.x

    • Response Back → K6 Processes Response
  6. Results Processing
    • Update Metrics → Log Results → Continue Test Loop

    • Upload to S3 → Organized S3 Structure

    • CloudWatch Dashboard → Download Script → Local Analysis

🌐 IP Address Assignment Process

Detailed IP Assignment Flow

IP Assignment Steps:

  1. Task Deployment
    • aws ecs run-task → ECS Scheduler
    • Fargate Platform
  2. Resource Allocation
    • Allocate CPU: 1024 units
    • Allocate Memory: 2048 MiB
    • Allocate Network: awsvpc mode
  3. Network Interface Creation
    • Create ENI in VPC
    • Assign Private IP from Subnet
    • 10.0.1.x from 10.0.1.0/24
  4. Public IP Assignment
    • Public Subnet Configuration
    • map_public_ip_on_launch = true
    • Auto-assign Public IP
    • 3.x.x.x from AWS IP Pool
  5. Network Configuration
    • Route Table Configuration
    • 0.0.0.0/0 → Internet Gateway
    • Security Group Rules
    • Allow all outbound traffic
  6. Task Ready
    • Task Status: RUNNING
    • Container can access internet
    • K6 can reach target application

IP Assignment Code Reference

# VPC Configuration resource "aws_vpc" "k6_vpc" { cidr_block = "10.0.0.0/16" enable_dns_hostnames = true enable_dns_support = true } # Public Subnet with Auto-assign Public IP resource "aws_subnet" "k6_public_subnet" { vpc_id = aws_vpc.k6_vpc.id cidr_block = "10.0.1.0/24" availability_zone = "us-east-1a" map_public_ip_on_launch = true # ← Enables auto-assign } # Internet Gateway for Internet Access resource "aws_internet_gateway" "k6_igw" { vpc_id = aws_vpc.k6_vpc.id } # Route Table for Internet Access resource "aws_route_table" "k6_public_rt" { vpc_id = aws_vpc.k6_vpc.id route { cidr_block = "0.0.0.0/0" # ← All traffic to internet gateway_id = aws_internet_gateway.k6_igw.id } } # ECS Task with awsvpc Network Mode resource "aws_ecs_task_definition" "k6_task" { network_mode = "awsvpc" # ← Required for public IP requires_compatibilities = ["FARGATE"] cpu = 1024 memory = 2048 }

🚀 Test Execution Lifecycle

Complete Test Execution Flow

Test Execution Steps:

  1. Container Startup
    • Fargate Starts Container → Docker Image Pulled
    • Container Entry Point → /scripts/run-k6-with-upload.sh
  2. Environment Setup
    • Set Environment Variables
    • TARGET_URL=https://affluenceit.com/
    • TEST_TYPE=basic
    • S3_BUCKET=k6-load-test-results-xxx
    • AWS_REGION=us-east-1
  3. K6 Initialization
    • k6 run /scripts/basic-load-test.js
    • Load Test Script Parsed → Test Configuration Applied
    • VUs Initialized
  4. Virtual User Execution
    • VU 1 Starts → Generate HTTP Request
    • VU 2 Starts → Generate HTTP Request
    • VU N Starts → Generate HTTP Request
  5. Network Processing
    • Container Network Stack → Public IP: 3.x.x.x
    • Internet Gateway → Internet
    • Target Application
  6. Response Processing
    • HTTP Response → K6 Processes Response
    • Update Metrics → Log Results
    • Continue Test Loop
  7. Test Completion
    • All VUs Complete → Generate Results Files
    • Upload to S3 → Container Stops

K6 Script Execution Flow

// basic-load-test.js - Execution Flow import http from 'k6/http'; import { check } from 'k6'; // 1. Setup Phase (runs once) export function setup() { console.log(`Starting load test against: ${__ENV.TARGET_URL}`); return { targetUrl: __ENV.TARGET_URL }; } // 2. Main Test Function (runs per VU iteration) export default function (data) { // Each VU executes this function const response = http.get(data.targetUrl, { insecureSkipTLSVerify: true }); check(response, { 'status is 200': (r) => r.status === 200, 'response time < 2000ms': (r) => r.timings.duration < 2000, }); } // 3. Teardown Phase (runs once) export function teardown(data) { console.log(`Load test completed for: ${data.targetUrl}`); }

S3 Upload Script Flow

#!/bin/bash # upload-to-s3.sh - Upload Process # 1. Configuration S3_BUCKET=${S3_BUCKET:-"k6-load-test-results"} S3_PREFIX=${S3_PREFIX:-"test-results"} TEST_TYPE=${TEST_TYPE:-"basic"} TIMESTAMP=$(date +%Y%m%d-%H%M%S) # 2. Create S3 Path S3_PATH="s3://${S3_BUCKET}/${S3_PREFIX}/${TEST_TYPE}/${TIMESTAMP}/" # 3. Upload Results if [ -f "/results/results.json" ]; then aws s3 cp /results/results.json "${S3_PATH}results.json" fi # 4. Upload All Files aws s3 cp /results/ "${S3_PATH}" --recursive # 5. Create Summary cat > /tmp/test-summary.json << EOF { "test_type": "${TEST_TYPE}", "timestamp": "${TIMESTAMP}", "target_url": "${TARGET_URL}", "s3_location": "${S3_PATH}" } EOF aws s3 cp /tmp/test-summary.json "${S3_PATH}test-summary.json"

🌐 Network Traffic Flow

Detailed Network Flow Diagram

Network Flow Steps:

  1. K6 Container
    • VU 1 → HTTP Request
    • VU 2 → HTTP Request
    • VU N → HTTP Request
  2. Container Network
    • Container Network Interface
    • Private IP: 10.0.1.x
  3. VPC Network
    • Public Subnet → Public IP: 3.x.x.x
    • Route Table → 0.0.0.0/0 → Internet Gateway
  4. Internet
    • Internet Gateway → Internet
    • Target Application → HTTPS Response
  5. Response Path
    • Internet → Internet Gateway
    • Public IP: 3.x.x.x → Private IP: 10.0.1.x
    • Container Network Interface → K6 Processes Response

🎯 Summary

This flowchart document provides:

Key Flow Components

  1. IP Assignment: From task deployment to public IP assignment
  2. Test Execution: Complete lifecycle from container start to completion
  3. Network Flow: Detailed traffic routing through VPC
  4. Results Processing: From local generation to S3 storage
  5. Monitoring: Real-time metrics and log collection

Fargate Role in Each Flow

  1. Resource Allocation: CPU, memory, and network resources
  2. Network Integration: awsvpc mode with public IP assignment
  3. Task Management: Start, stop, and monitor container execution
  4. Logging: Integration with CloudWatch for real-time monitoring

Benefits of This Architecture

  1. Clear Data Flow: Each step is documented and traceable
  2. Scalable Design: Easy to add more tasks or modify flows
  3. Comprehensive Monitoring: Multiple data collection points
  4. Cost Optimization: Pay only for actual execution time
  5. Security: Proper network isolation and access controls

The flowcharts demonstrate how AWS Fargate seamlessly integrates with other AWS services to provide a complete, serverless load testing solution.
