HMAC-Based Request Validation

Complete Flowchart and Implementation Guide

🔐 What is HMAC Validation?

HMAC (Hash-based Message Authentication Code) is a cryptographic method that combines a secret key with a hash function to create a unique signature for data. This ensures both authentication and integrity of HTTP requests.

🔍 Key Components:

  • Secret Key: Shared between client and server
  • Hash Function: Usually SHA-256 or SHA-512
  • Payload: Request data to be signed
  • Signature: Generated HMAC value
  • Timestamp: Prevents replay attacks

🛡️ Security Benefits

🔑 Authentication

Only parties with the secret key can create valid signatures. This prevents unauthorized access and ensures requests come from trusted sources.

// Only valid clients can create signatures const signature = createHMAC(payload, secretKey); // Server validates: signature === expectedSignature

🔒 Integrity

Any modification to the payload changes the signature. This detects tampering, corruption, or man-in-the-middle attacks.

// Original payload const payload1 = '{"userId": "123"}'; const sig1 = createHMAC(payload1, key); // Modified payload const payload2 = '{"userId": "456"}'; const sig2 = createHMAC(payload2, key); // sig1 !== sig2 (detects tampering)

📝 Non-repudiation

Proves the request came from the expected source. The sender cannot deny sending the request due to cryptographic proof.

// Server logs: "Request from client with valid signature" // Client cannot deny sending the request // Cryptographic proof exists

⏰ Replay Protection

Timestamp validation prevents old requests from being reused. This stops replay attacks where attackers capture and replay valid requests.

// Check if request is recent const timeDiff = currentTime - requestTime; if (timeDiff > 300) { // 5 minutes reject("Request too old"); }

💻 Implementation Examples

🔧 JavaScript/Node.js Implementation

const crypto = require('crypto'); // Client-side: Create signature function createHMACSignature(payload, secretKey, timestamp) { const data = payload + timestamp; const hmac = crypto.createHmac('sha256', secretKey); hmac.update(data); return hmac.digest('hex'); } // Server-side: Validate signature function validateHMACSignature(payload, signature, timestamp, secretKey) { // Check timestamp (5 minute window) const currentTime = Math.floor(Date.now() / 1000); if (Math.abs(currentTime - timestamp) > 300) { return false; // Replay attack } // Recreate signature const expectedSignature = createHMACSignature(payload, secretKey, timestamp); // Compare signatures return signature === expectedSignature; } // Usage example const payload = JSON.stringify({ userId: "123", action: "validate" }); const timestamp = Math.floor(Date.now() / 1000); const secretKey = "your-secret-key"; const signature = createHMACSignature(payload, secretKey, timestamp); console.log('Signature:', signature); console.log('Valid:', validateHMACSignature(payload, signature, timestamp, secretKey));

✅ Best Practices

🔐 Secret Key Management

  • Store secrets in environment variables
  • Use AWS Secrets Manager or similar
  • Rotate keys regularly (every 90 days)
  • Never expose keys in code or logs
  • Use different keys for different environments

⏰ Timestamp Validation

  • Include timestamp in signature calculation
  • Set reasonable time windows (5-15 minutes)
  • Use UTC timestamps consistently
  • Log timestamp validation failures
  • Consider clock skew between systems

📋 Signature Headers

  • Use consistent header names (X-Signature)
  • Include algorithm information if needed
  • Consider multiple signature algorithms
  • Use Base64 or hex encoding consistently
  • Document header requirements

🚨 Error Handling

  • Don't reveal signature details in errors
  • Log validation failures for monitoring
  • Return consistent error responses
  • Implement rate limiting on failures
  • Monitor for attack patterns

📊 Summary

🎯 HMAC Validation Provides:

  • Authentication: Verifies request comes from trusted source
  • Integrity: Ensures data hasn't been tampered with
  • Non-repudiation: Provides cryptographic proof of origin
  • Replay Protection: Prevents reuse of old requests

🔧 Implementation Checklist:

  1. Choose a strong hash algorithm (SHA-256 recommended)
  2. Generate and securely store secret keys
  3. Include timestamp in signature calculation
  4. Implement proper error handling
  5. Add monitoring and logging
  6. Test with various attack scenarios
  7. Document the validation process
